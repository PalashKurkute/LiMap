# Implementation Plan — From Audited Skeleton to Defensible Prototype

**Source:** `skeptical_judge_audit.md` (self-audit against `SIH26053_Standards_To_Beat.md`)
**Current state:** ~30% of standards genuinely cleared, ~45% of headline metrics fabricated/clamped/circular, 0% of tests currently runnable (missing data files).
**Goal of this plan:** Not "build everything the standards file asks for" — that's unrealistic in the time left. The goal is **eliminate every claim that would embarrass the team in front of a judge**, then spend remaining time converting your best-built modules from "correct in isolation" to "proven on real data."

---

## How to read this plan

Each phase has a **Definition of Done** you can literally check off. Phases are ordered by risk, not by difficulty — Phase 0 is first because a fabricated number sitting in a submitted report is a *worse* outcome than an honestly-labeled missing feature. A judge forgives "we didn't get to X." A judge does not forgive "you told me a number that isn't real."

Do not skip Phase 0 to go work on "cooler" features. Every hour spent adding a new capability on top of an unfixed fabrication is an hour that increases how bad the eventual discovery looks.

## Phase 1 — Get one real dataset actually flowing end-to-end (2–3 days)

You cannot fix "no real data" by generating more synthetic data. You need at least one real public sequence moving through the *entire* pipeline once.

- [ ] Download **SemanticKITTI sequence 08** specifically (this is the exact sequence VRgrid and multiple rivals benchmark against — using the same one lets you make direct, credible comparisons).
- [ ] Wire `loader.py` (already written, per the audit, to correctly parse `.bin`/`.label` files) to actually read it. This is a plumbing task, not new code — the audit confirms this file "would work" on real data.
- [ ] Run the full pipeline — ingestion → grid insertion → costmap — on this one real sequence, even if the output is unimpressive. **An unimpressive number from real data is worth more than an impressive number from synthetic data.**
- [ ] Regenerate `BENCHMARK_REPORT.md` with a clearly separated section: "Real-data results (SemanticKITTI seq. 08)" vs "Synthetic stress-test results" — never blend the two in one table again.
- [ ] If disk/compute is a constraint, use a **short 500–1000 frame subset**, not the full sequence — a small real result beats a large fake one.

**Definition of Done:** At least one metric in the report (doesn't have to be mIoU yet — could just be "ingested N real frames, grid stayed under memory bound, zero crashes") is traceable to a real public dataset run, end to end.

## Phase 2 — Wire the standalone modules into the actual pipeline (2–3 days)

The audit found several modules that are *correctly implemented but never called* by the main data path. This is the cheapest, highest-leverage fix in the whole plan — the code already exists, it just needs to be connected.

- [ ] **`DualElevationExtractor` → `spatial_hash.py`'s `_insert_batch()`.** Right now overhang detection uses a crude `max - min > 1.5` threshold instead of the properly-built dual-elevation analysis. Replace the threshold call with the real extractor. This single change legitimately upgrades Standard 1.4 from "Partially" to "Yes."
- [ ] **Chan's parallel-variance merge (`welford_fusion.py`) → an actual coarsening/query path.** This is the code behind Standard 2.2 (uncertainty-preserving coarsening), and the audit found it's implemented but never invoked — there is currently no code path that merges fine cells into a coarse cell at all. Build the merge operation into your ring-boundary logic: when a query asks for a coarser view (or when memory pressure triggers a merge), call the existing Chan's-merge function instead of writing new math. **This is finishing work, not new research.**
- [ ] **`local_plane.py`'s PCA ground-fit → the main grid insertion pipeline.** Currently a standalone utility only exercised by its own synthetic test. Call it during real cell insertion so slope-handling is live, not theoretical. This directly answers the standards file's flagged whitespace item (§4.4 — the exact gap the strongest rival admits it hasn't closed).
- [ ] **`CostmapGenerator`'s `uncertainty_weight` → confirm it's actually driving `hybrid_a_star.py`'s search**, not just multiplying a number that never reaches the planner. Add one integration test: construct a map with one clearly high-confidence path and one clearly low-confidence-but-shorter path, and assert the planner picks the high-confidence one. This is the concrete, end-to-end proof for Standard 2.3 the audit says is currently unproven.

**Definition of Done:** Every module the audit listed as "correct but never called" now has at least one call site in the live pipeline, and one integration test proving it affects the final output (not just a unit test proving the module works in isolation).

## Phase 3 — Replace the fake segmentation with a real, small, honestly-scoped one (3–5 days)

This is your single weakest claim per the audit — fix it before anything else in this phase list.

- [ ] Do **not** train a segmentation network from scratch — no time, and the "5.01% mIoU, worse than random" failure mode from a rival repo (documented in your own standards file) is exactly what happens when you try.
- [ ] Use a **pretrained** checkpoint instead: Open3D-ML ships pretrained RandLA-Net weights for SemanticKITTI. Two rival repos already use this exact approach — it's proven, low-risk, and fast to integrate.
- [ ] Export/convert to ONNX (this is what `segmentation_infer.py`'s dead ONNX path was already built to expect — you're filling in the missing half of code that already exists).
- [ ] Run it on your Phase 1 real-data sequence. Report the **real mIoU**, by distance band, on SemanticKITTI validation data — even if it's mediocre. State clearly: "pretrained RandLA-Net, not fine-tuned by us" — this kind of narrow, honest scoping is exactly what the standards file's §6.4 (originality/citation) asks for.
- [ ] Delete the geometric-heuristic mIoU claim from the headline report entirely, or relabel it clearly as "fallback mode when no model is available" — never let it masquerade as the primary result again.

**Definition of Done:** A judge asking "what's your mIoU on SemanticKITTI val, by distance band?" gets a real number from a real model, with the model's provenance stated in one sentence.

## Priority order if you run out of time

If you can only do a subset of this plan, do it in this order — each phase is a strict prerequisite in credibility terms for the one after it being worth anything:

1. **Phase 0** (remove lies) — always, no exceptions, regardless of remaining time.
2. **Phase 1** (one real dataset flowing) — this alone converts "impressive but fake" into "modest but real," which is the single most important credibility shift available.
3. **Phase 2** (wire existing modules) — cheapest real capability gains available, since the code already exists.
4. **Phase 3** (real segmentation model) — fixes your single named weakest claim.
5. Phases 4–6 as time allows.
